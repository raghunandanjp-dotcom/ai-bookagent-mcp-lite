# Advanced local Canva Connect mode (v1)

Canva is optional. The normal book workflow needs no Canva account, OAuth settings, or secret. This v1 mode is for developers and power users who deliberately configure **their own Canva Public Integration** on their own machine. It is not an Enterprise integration and is not the planned ordinary-user hosted product; Canva's general guidance to use a secure backend remains applicable to that future product.

## What it does

After a separate, explicit per-book consent action, the local CLI regenerates the canonical PPTX from the approved `BookDesign`, verifies its source/design/illustration bindings and SHA-256, and sends that PPTX as a direct binary request to Canva's Import API. It waits for a completed import, accepts only a trusted Canva HTTPS edit URL: either `/design/{id}/edit` or Canva’s documented temporary `/api/design/{opaque-token}/edit` return-navigation form. It records the returned design ID and edit URL separately in the local project only then.

There is no public URL, manual upload, host-artifact file reference, template selection, or prompt-based redesign route. The PPTX is generated by this program; callers cannot provide a PPTX path. Once Canva accepts an import job, its non-secret job ID and the exact source/design/illustration/PPTX bindings are saved before polling, together with the SHA-256-verified local binary source under a guarded pending path. A timed-out rerun with unchanged bindings verifies and polls that exact source/job rather than uploading another file; any mismatch is rejected. The retained binary is deleted when the job reaches a terminal success or failure state. Imported text and basic shapes are editable in Canva. Approved illustrations are editable as whole image assets (move, resize, replace); their internal pixels/components are not separately editable.

## One-time Public Integration setup

In Canva's Developer Portal, create a Public Integration for your own use and configure exactly:

- scopes: `design:content:write` and `design:meta:read`;
- redirect URI: `http://127.0.0.1:3001/oauth/callback`.

Do not paste the client secret into chat, an MCP call, a project manifest, a `.env`, shell history, or a command argument. In an interactive terminal run:

```text
ai-bookagent canva configure
```

On Windows, `configure` first starts a short-lived loopback-only browser page and prints its local `http://127.0.0.1:<port>/` URL. Open that URL yourself and paste the visible client ID and password-field client secret normally in the browser; the CLI does not claim that `Ctrl+V` works in every integrated PowerShell terminal. The page accepts one POST, sends the values directly to Windows Credential Manager through the existing local vault path, displays no secret, writes no plaintext file, and closes the listener (the completion page asks the browser to close itself). The CLI then starts the OAuth callback listener on the exact configured `127.0.0.1:3001` redirect, prints the Canva authorization URL, uses OAuth authorization-code PKCE, and stores the refresh-token lifecycle outside the project. It never auto-opens either browser page. Closing or ignoring the setup page times out safely without storing a credential. The permission notice at Canva is the moment to review the data-transfer consent for your integration.

Use these non-secret local commands:

```text
ai-bookagent canva status
ai-bookagent canva disconnect
ai-bookagent canva consent /absolute/path/to/book-project
ai-bookagent canva import /absolute/path/to/book-project
```

`consent` is the explicit per-book action. `import` refuses unless consent is current and all of these are unchanged: source revision, approved design revision, page count, complete approved-illustration digest, accepted DOCX binding, and newly generated PPTX SHA-256. A changed book requires a new approval and consent.

## Credential storage and platform policy

No token, client secret, authorization code, Authorization header, or API error payload is emitted in CLI/MCP output or recorded in project state. v1 uses the current OS user’s vault, not a plaintext settings file. It stores the client ID/secret and the current refresh token, refreshing and rotating it locally when Canva returns a replacement.

- Windows is supported through the native Credential Manager API (`CredRead`, `CredWrite`, `CredDelete`, and `CredEnumerate`) invoked by a fixed, noninteractive PowerShell P/Invoke helper. Credential Manager limits one blob to 2,560 bytes, so a value is stored in a bounded generation of 2,560-byte chunks (at most 32 chunks and 64 KiB total). A compact manifest containing the generation, chunk count, byte count, and SHA-256 is written last; readers validate all of it before returning any value. A missing, partial, or altered generation fails closed, while stale chunks are cleaned after a successful commit and on disconnect. The helper source contains no secret; values move only over its stdin pipe and are zeroed before temporary unmanaged buffers are freed. PowerShell execution policy is not changed and `npm.ps1` is not used.
- Linux is supported only when `secret-tool` from libsecret is present and usable. Secret values are supplied on standard input, never command arguments.
- macOS is intentionally **not enabled in this build**: the package does not yet ship and exercise an equivalent native Keychain bridge that can accept a secret without exposing it to command arguments. The CLI fails closed with `secure_storage_unavailable`; it does not substitute Keychain command-line passwords, `.env`, or project-local secrets.
- Unsupported systems, locked vaults, and absent vault utilities fail closed. They do not fall back to plaintext storage.

`disconnect` deletes the local vault record. Revoke the integration/token in Canva's Developer Portal as well if a device is lost, an account changes, or a secret might be exposed; then run `configure` again. Local project files retain only the resulting design ID/edit URL and normal non-secret workflow metadata.

## Safe OAuth diagnostics

The local terminal never prints Canva's token response body, authorization code, request headers, or credential values. If the token exchange fails after the loopback callback, it emits only a structured non-secret diagnostic with `phase: "token_exchange"`, an HTTP status when one exists, and one of these classifications:

- `client_auth_rejected` (`401`): the integration's client authentication was rejected. Inspect the client ID/secret in the Developer Portal without pasting them into chat or logs.
- `request_or_grant_rejected` (`400`): the redirect/integration configuration or one-time authorization grant was rejected. Confirm the exact registered redirect URI; a new browser authorization is needed for a new code.
- `integration_access_denied` (`403`), `rate_limited` (`429`), `canva_service_error` (`5xx`), `transport_error`, or `response_shape_invalid`.

This classification deliberately cannot identify Canva's provider-specific error code because that would require retaining or printing an error payload. The request uses Canva's documented `POST /rest/v1/oauth/token`, `application/x-www-form-urlencoded` body, Basic `{client_id}:{client_secret}` authentication, authorization code, PKCE verifier, and redirect URI.

## Failure contract and residual risks

The import command returns a structured non-secret result:

```json
{ "outcome": "failed", "code": "consent_required", "message": "A fresh explicit Canva consent for this approved design is required.", "retryable": false }
```

Retryable failures cover a temporary token/API/import wait failure. Stale source, changed assets, missing consent, malformed Canva response, and unavailable secure storage fail closed. The CLI does not independently establish visual fidelity after Canva converts a PPTX; users must review page order, text wrapping, fonts, Kannada glyphs, clipping, and image placement in Canva before publication. Kannada remains experimental and needs fluent-language and rendered-glyph review.

The test suite uses only mocked OAuth and HTTP. Do not use automated tests to authorize an account or import a real book.
